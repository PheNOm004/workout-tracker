# Night Training Console Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-theme and restructure TimeGo's existing Log, Progress, and Routines UI into the approved dark-first Night Training Console with semantic fitness color, active-workout hierarchy, and one consistent motion language.

**Architecture:** Keep the existing Compose navigation, view models, domain functions, charts, diagrams, and Room data unchanged. Replace the shared theme tokens first, then add small reusable presentation primitives (`TrainingPulse` and motion specs), and finally roll the system through Log, Progress, Routines, and navigation. Each screen task is presentation-only and independently build-verifiable.

**Tech Stack:** Kotlin, Jetpack Compose, Material 3, Navigation Compose, existing Manrope and JetBrains Mono bundled fonts, Gradle Android build, existing JUnit domain test suite.

**Spec:** `docs/superpowers/specs/2026-08-16-timego-night-training-console-design.md`

## Global Constraints

- Dark mode is the primary composition; keep a deliberate warm light companion.
- Do not change domain rules, workout recommendations, Room schema, persistence, chart/diagram math, navigation destinations, or screen count.
- Coral is reserved for action, focus, selection, and meaningful performance moments; mint, amber, and violet are semantic data colors.
- Manrope remains UI/body type; JetBrains Mono remains numeric/data type.
- Motion must be grouped, interruptible, directionally coherent, and compatible with reduced-motion behavior.
- Run `./gradlew assembleDebug` after each foundation or screen task and `./gradlew testDebugUnitTest` before handoff.
